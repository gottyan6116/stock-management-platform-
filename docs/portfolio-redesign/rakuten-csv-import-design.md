# 楽天証券 保有商品CSV取込 設計案（提案のみ・未実装）

## 前提と未確定事項

- 対象: 楽天証券の「保有商品一覧」CSV（ログイン後 → 資産残高・保有商品 → CSVで保存）。
- **実CSVの列名・文字コード・区切りは、サンプルを見るまで確定できません。** 楽天証券は Shift_JIS（CP932）で、国内株・投信・米国株でヘッダーが異なる（別セクションに分かれている）ことが多いと想定していますが、これは推測です。
- 依頼: 数字と銘柄名をマスクした（または少数行だけ残した）サンプルCSVを1つ共有してください。共有後に列マッピングを確定します。

## 方針

1. **取り込みは「差分プレビュー → 確認 → 反映」の2段階。** ファイルを選んだだけでは DB を変更しない。
2. **既存の保有を黙って上書き・削除しない。** 反映前に「追加 / 数量・取得単価の更新 / CSVに無いので変更なし」を一覧で見せる。CSVに無い保有は削除しない（手入力ファンド等を守るため）。
3. **不明な銘柄は取り込まず、理由を出す。** コード解決できない行は「未対応（手入力が必要）」に分けて表示。

## 処理フロー

```
CSVを選択（クライアント）
  → CP932 でデコード（TextDecoder("shift_jis")）
  → セクション分割・ヘッダー検出（国内株 / 投信 / 米国株）
  → 行を正規化: { kind, code, name, quantity, avgCost, account, currency }
  → POST /api/positions/import/preview   （DB 変更なし。突合結果を返す）
  → 画面で差分確認（モーダル）
  → POST /api/positions/import/apply     （確認済みの行だけ反映）
```

## 突合ルール

| 種別 | キー | 補足 |
|---|---|---|
| 国内株 | 証券コード4桁 → `NNNN.T` | 既存 instruments と一致するものを優先 |
| 米国株 | ティッカー | 通貨 USD |
| 投資信託 | ファンド名（コードが無いため名称の正規化一致） | 完全一致のみ自動、曖昧なら候補を提示して選択 |

- 口座区分（特定 / NISA成長 / NISAつみたて）は CSV の「口座」列から `nisa_type` に写像。旧つみたてNISAは `nisa_legacy=true`。
- 投信の取得単価は **1万口あたり**（現行仕様と揃える）。CSV が1口あたりなら ×10,000 して格納する。この単位はサンプルで必ず確認する。
- 取込時に `position_purchases`（source='csv'）へは書かない（保有CSVは買付日を持たないため）。NISA年間消化には約定履歴CSVが別途必要（後述）。

## 検証（実装時のテスト）

- 文字コード: CP932 の日本語ヘッダーが化けないこと。
- 数値: `1,234,567` のカンマ、`--` / 空欄は null（0 にしない）。
- 冪等性: 同じCSVを2回取り込んでも2回目は「変更なし」になること。
- 破壊防止: CSV に無い保有が消えないこと。

## NISA消化額（別CSV）

年間投資枠の消化は買付日と金額が必要なため、**「取引履歴（約定）CSV」** の取込が正攻法です。保有CSVだけでは復元できません。
当面は購入履歴テーブル（0008）へ手入力、約定履歴CSVは第2段として同じ設計で追加する、を提案します。
